# 红点、HTTP 与新手引导审查

审查日期：2026-09-23。范围包括框架服务、Scope 使用期、显示组件、业务示例、自动绑定、预制体、中文 API 与使用文档、单元测试及 Creator 浏览器预览。审查后的当前范围内未发现未修复的阻塞问题。

## 已修复问题

1. **引导入场和换步闪屏。** 原实现每步重新铺白色，并在点击后立即隐藏遮罩。改成整次引导共用一个 presentation：首次灰色渐入，步骤完成保留最后一帧，下一目标准备好后平移、缩放并插值圆角。白色只用于描边。圆形、圆角矩形与直角矩形共用几何表达。
2. **全面屏边缘漏遮挡。** Canvas 设计矩形不等于正交 UI 相机实际显示区域；改用相机视口反投影覆盖灰色填充和透明输入层。真实鼠标验证顶部返回按钮不能穿透。
3. **形状与输入范围不一致。** 输入层检查实际镂空形状和真实目标 Button 的交集；圆形包围盒角落、亮区留白、等待准备及动画中途都不放行。结束时恢复输入层原来的公开 hitTest 方法。
4. **圆形描边退化。** 完整圆形使用 Graphics.circle，避免圆角矩形零长度边的描边尖点；中间形状继续使用圆角矩形插值。
5. **红点批处理中首次订阅重复通知。** 记录每个订阅者最近交付值，避免先立即回调再收到同值批量通知；注册和订阅复制稳定 Key，外部可变输入不影响销毁或后续写入。
6. **请求 URL 类型混淆。** 明确识别协议，非法绝对地址不再回退拼成 baseUrl 下的相对路径。带 URL 凭据和非 HTTP 协议在发送前拒绝。
7. **运行中的引导定义被外部修改。** 启动复制 ID、版本、跳过策略和步骤配置，使本次执行及检查点保持一致。
8. **旧红点解绑句柄误删新订阅。** 旧句柄第二次调用会删除同一 Key 的新订阅组。现在先检查监听是否仍有效，再确认 Map 内仍为原订阅组才移除；覆盖重复解绑、旧 owner 关闭、新订阅继续通知和状态域结束后的重复释放。
9. **HTTP 同步取消遗留未处理拒绝。** transport 在 send 内取消 owner 时，`untilCancelled` 先同步抛错，漏接传输 Promise。现在即使信号已取消也接管原 Promise 的拒绝，同时保留同步抛出取消的约定。单测覆盖立即拒绝、迟到拒绝、计时器和子 Scope 归还，并由 node:test 检查未处理拒绝。

## 修复后复审

本轮再次检查红点解绑、共用取消接口的调用方、HTTP 错误分类，以及引导目标租约、连续聚焦和取消清理。虚拟列表一并复审：修复 Part 清理屏障丢失异常，并进一步修复关闭期间错误未传递给 dispose 的问题，详见 [虚拟列表审查](virtual-list-review.md)。新增回归测试均先在旧实现上失败，再在修复后通过；当前未发现其他可复现的缺陷。`validate_scene` 的日志汇总仍包含修复前故意失败的回归日志和历史构建记录，未把该汇总误记为通过。

## 生命周期与业务边界

- 红点来源属于业务服务/账号有效期，页面和复用条目只持有短期订阅；重复绑定解除旧订阅，来源注销立即归零。任务示例在持久化成功后更新，外部领取也会刷新，写入失败保持旧数量。
- 每个 HTTP 请求拥有独立子 Scope、计时器和取消信号。XHR 与微信适配尽可能物理 abort；不配合的底层任务可以迟到，但不会回写已取消的调用方。服务端写入不能通过客户端取消回滚，默认没有自动重试。
- 引导目标按一次注册分配租约。条目复用后旧租约不再有效；步骤任务、子任务和异步清理排空之后才保存进度和启动下一步。取消、跳过、目标消失及页面退出均移除对应等待与监听。
- 通用框架不依赖业务模块，不内置奖励规则或业务预制体。业务条目复用既有 Part、VirtualList、Scope 和自动绑定；HTTP 页面复用 Actions.latest。

## 当前边界

本轮验证的是 Creator 3.8.8 浏览器预览和本机真实 HTTP，尚未执行本轮微信/原生构建及真机验收。微信传输仅验证注入合同。引导支持同一正交 Canvas 下的轴对齐目标及矩形祖先裁剪；复杂旋转、任意 Mask 和其他页面覆盖需业务控制。超时/取消采用协作式任务退出，不配合取消的业务 Promise 仍可阻止引导排空。截图和实例数不是设备性能结论。
