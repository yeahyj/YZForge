# 通用 UI 组件审查

审查日期：2026-09-23。当前范围为 SafeWidget、AsyncButton、AsyncSprite、CountdownLabel、Switch、MarqueeLabel，以及原生子类参与 UI/Part/列表生命周期的适配。

## 接口与职责

- AsyncButton、AsyncSprite、CountdownLabel 分别直接继承 Button、Sprite、Label，同节点不再叠加对应原生组件。原生属性、输入、过渡和渲染生命周期保留，自动绑定仍能取得原生类型引用。
- Switch 只切换直接子节点。支持索引、多选、名字、全部隐藏、编辑器事件；按名字选择同步保存索引，重新启用保持选择，数组读取不会暴露内部状态。
- 移除 ViewState、复杂 TabGroup、专用动态页签 Part 和旧的一次性制作脚本。业务四态直接用 Switch，动态内容仍由业务通过现有 Part 管理。
- MarqueeLabel 管理固定裁剪区域和自动创建的 Label 子节点，短文本静止，长文本往返滚动。Mask 与 Label 的分层由组件处理，不要求使用方手工搭建。
- 普通按钮和倒计时已在独立节点验证，不依赖 GameComponent 注入。逻辑图片资源仍使用所属模块 Assets，框架 UI/Part 自动注入；独立场景直接使用原生 spriteFrame，逻辑资源加载接入已有 app.bindScene。

## 清理与复审

原生子类中的 ComponentScope 是普通 TypeScript 对象，不向节点额外添加脚本。现有实例遍历通过 ComponentBinding 同时收集 GameComponent 和原生扩展；UI 关闭、Part 停用与 VirtualList 复用都会等待完整清理。

复审并修复了停用排空期间再次 bind 的边界：新订阅不能落到旧清理快照之外，清理完成前明确报 UI_COMPONENT_DRAINING。普通 run 在这一阶段返回 false。显式绑定允许首次激活前配置，旧句柄只关闭自己的 Scope。

已经验证取消先同步停止回写与监听，随后等待物理 Promise、异步清理和资源归还；再次启用等待旧工作结束。按钮忙碌覆盖清理阶段，图片只允许最新请求回写，倒计时到期通知只发生一次。任务仍须响应取消，组件不能强制终止不合作的 Promise。

滚动文字只移动自有子节点，不改根节点的位置和尺寸。文字与样式稳定时不会每帧强制重建文字贴图；文本、字体或宽度改变会重算并回到开头。禁用停止更新，重复启用不重复创建子节点。

| npm run test:showcase | 11 项业务测试通过                                                                                |

| 资源与生命周期        | 迟到加载、重绑、旧句柄、占位/失败图、取消提交、完成回调、Scope 归还通过                          |
| VirtualList           | 一万行、定位、网格、局部刷新、清理异常回收及关闭回归通过；新增原生按钮任务与异步清理阻挡复用检查 |
| 红点、网络与引导      | 真实 HTTP、聚焦动画/输入、目标回收及关闭清理回归通过                                             |

类型合同明确验证 AsyncButton 可赋给 Button、AsyncSprite 可赋给 Sprite、CountdownLabel 可赋给 Label，同时检查错误资源类型、索引类型与父期限关闭权限。删除了已移除页签功能的测试，新增滚动计算测试。

预制体通过当前 Cocos MCP、Creator 组件 API、序列化和 AssetDB 更新；保留示例根节点、现有布局和原生组件 fileId，替换组件引用后重新生成自动绑定。原生控件替换及删减页签是本次有意的结构变更，没有修改 .scene 文件。实际预览截图位于忽略目录 temp/mcp-captures。

validate_scene 的当前脚本诊断通过，但其历史日志扫描仍会匹配旧失败记录及迁移过程中短暂的重复渲染组件、编译入口过渡记录，因此不声称该日志汇总全绿。最终独立预览窗口没有非预期运行错误；旧日志保留，资产刷新后没有相同问题重现。

## 验证边界

实际验证为 Creator 3.8.8 浏览器预览和编辑器，包含手机纵屏、横屏及已有平板回归场景，未验证微信或原生真机。SafeWidget 仍限定同一正交 Canvas 的轴对齐、正缩放固定布局。MarqueeLabel 为单行普通文本，不包含富文本排版；字体资源遵循原生 Label 行为。
