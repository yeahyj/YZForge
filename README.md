# YZForge

基于 **Cocos Creator 3.8.8** 的通用游戏框架，面向小游戏、Web 和原生项目。提供模块与资源包管理、UI、自动绑定、音频、配置表、时间及本地存档，并配有 Creator 工作台。

可以直接复制本项目开始开发。项目自带可运行的示例，也支持清理示例后从空框架开始。

| -------------- | -------------------------------------------------------------------------------------------------------- |

## 快速开始

环境要求：

- **Cocos Creator 3.8.8**。
- **Node.js 22.x（22.13 及以上）或 24 及以上版本**。
- 推荐使用 VS Code，安装工作区推荐的 **ESLint** 和 **Prettier** 插件。

使用步骤：

1. 将项目复制到新目录，保留 `.meta` 和项目设置，排除缓存、构建产物及本机配置。文件清单与标识设置见 [复制项目与清理示例](docs/copy-project.md)。
2. 在项目根目录执行 `npm ci`。
3. 用 Creator 打开项目，等待资源导入和脚本编译完成。
4. 确认项目扩展 `yzforge-editor` 已启用，打开 **YZForge → 项目工作台**。
5. 打开 [Bootstrap.scene](assets/game/boot/Bootstrap.scene)，运行预览。

预览首先进入“功能实验室”。建议先体验“正式业务流程 · 任务奖励”，再打开工作台的“示例工作流”，对照 Service、Presenter、Page 和 Part 的真实代码。其他入口展示 UI、资源、配置、时间、音频、存档与失败恢复。

- [正式开发工作流](docs/development-workflow.md)：从创建模块到业务、渲染、绑定和验证。
- [功能展示与验证入口](docs/showcase.md)：可交互示例、编辑器步骤和自动化验证。

启动接入点是 [start-game.ts](assets/game/app/start-game.ts)，在这里选择首屏。`GameRoot` 负责框架装配和启动状态显示，`app/generated` 由工作台生成。业务规则、状态、页面以及多步业务协调都放在所属模块的 `code` 中。页面通过 `show.ui` 打开其他界面和返回；单纯跳转不需要再写一个导航类。

项目附带 `showcase`、`workshop`、`lobby`、`profile`、`common` 五个示例模块，展示功能实验、任务流程、界面交互、共享服务和公共配置。示例模块可以按需清理，具体见 [示例应用说明](docs/example-app.md)。

## 项目结构

```text
assets/
├─ framework/                    # 框架运行时
└─ game/
   ├─ boot/                      # Bootstrap 场景和 GameRoot
   ├─ app/                       # 启动接入与应用装配
   │  ├─ start-game.ts           # 选择首屏或接入业务流程
   │  └─ generated/              # 模块装配、资源路由和运行参数
   └─ modules/                   # 业务模块
extensions/yzforge-editor/        # Creator 工作台
config-source/                   # XLSX 源工作簿
project-settings/                # 框架参数、资源身份和生成记录
settings/                        # Creator 项目设置及 Bundle 预设
tools/yzforge/                   # 生成、校验和构建工具
tests/                           # 自动化测试
docs/                            # 使用文档
```

包含代码与资源的模块使用以下结构；工作台按所选模块类型创建相应目录：

```text
assets/game/modules/inventory/
├─ module.json                   # 模块声明、依赖、资源包及界面登记
├─ public.ts                     # 对外提供的模块引用和 API 类型
├─ contracts/generated/          # 资源 Key、明确公开的界面和配置合同
├─ code/
│  ├─ InventoryModule.ts         # 模块服务装配
│  ├─ ui/                        # 界面脚本及可选 Presenter
│  ├─ components/                # Part 和普通组件
│  ├─ services/                  # 业务服务
│  └─ generated/                 # 依赖引用和私有配置类型
└─ bundles/
   └─ default/                   # 一个资源 Bundle
      ├─ dynamic/                # 自动编目的动态资源
      ├─ static/                 # 通过编辑器引用使用的资源
      └─ yz-index.json           # 自动生成的动态资源索引
```

## 开发流程

### 创建模块

在工作台选择模块类型、依赖和资源包，确认文件预览后创建。模块可以包含业务代码、资源，也可以只包含其中一类。

代码可以随应用加载，也可以通过代码 Bundle 按需加载。**加载代码与初始化业务是两个阶段**：代码模块在首次使用其 API 或打开所属界面时初始化业务。按需代码模块的入口由工作台生成。

跨模块调用通过公开 API 或类型化事件完成。跨模块资源和配置使用公开的资源 Key、配置类型；模块内部实现放在自己的 `code` 目录。

### 创建界面与 Part

在工作台选择 Page、Popup 等界面类型，或创建可复用的 Part。工作台自动补齐脚本和预制体后缀，并在创建前展示文件名及路径。

在 Creator 中编辑预制体，用 `btn_confirm`、`lbl_title`、`spr_icon` 等名称标记需要访问的节点，再执行自动绑定。生成的 Binding 提供对应属性，节点引用由工作台写入，无需手动拖拽。

界面脚本负责渲染和输入；复杂的显示流程可以交给 Presenter，多个界面共享的业务状态放在模块 Service。UI 之间通过打开参数、返回结果或事件通信。

继承框架基类的业务脚本使用 `onShow`、`onHide`、`onActivate`、`onTick` 等框架生命周期，保留引擎 `onLoad`、`start`、`update` 等入口给框架使用。

### 放置和加载资源

资源包根目录是 `bundles/default` 或其他命名的包目录，`dynamic` 和 `static` 都位于包内：

- 通过代码按需加载的资源放在 `dynamic`，工具自动生成资源清单和类型化 Key。
- 只通过场景或预制体序列化引用使用的资源放在 `static`。
- 动态 Part 放在 `dynamic/prefabs`；仅用于嵌套引用的 Part 放在 `static/prefabs`。

优先使用生成的 Key 加载资源，也支持当前命名空间内的路径或唯一短名；存在重名时会列出候选并报错。资源实际打包归属由 Bundle 配置和 Creator 的引用规则共同决定。

代码与资源分别使用 **YZForge 代码配置**、**YZForge 资源配置** 两份 Bundle 预设，在 Creator 中统一调整各平台的交付方式。资源和配置的加载用法见 [API 使用指南](docs/api-guide.md)。

### 制作配置表

通过工作台创建或接入 XLSX，选择表、主键和目标资源包。工作簿的 `__config` 页保存导出设置，`__enums` 页定义枚举；数据表前四行依次填写字段名、类型、默认值和说明。

支持整数、浮点数、布尔值、字符串、命名枚举、外键、资源引用、向量、颜色、数组及可空类型。导出结果包括目标包内的 JSON 数据，以及 TypeScript 类型、枚举和加载入口。

跨模块使用的表应公开其配置类型，调用方通过该类型加载数据，框架按发布路由定位资源包。公共配置可以归属项目选择的任意模块。

含公式的工作簿需要先重算再正式导出。当前公式重算使用 **Windows 桌面 Excel COM**；工作台提供环境检查和重算操作。

### 管理使用期限与时间

`Scope` 表示任务、资源和订阅的使用期限。界面的 `show` 和 Part 的 `activation` 提供绑定当前期限的资源、配置、音频和时间 API；期限结束时由框架统一清理。异步结果通过对应上下文的 `commit` 更新界面。

时间 API 支持获取当前时间、格式化日期、服务器校时，以及按日、周、月、年通知。项目设置统一维护时区偏移、每周起始日和日切时间。自然周期变化使用 `onBoundary`；从现在起经过一段日历时间使用 `afterPeriod`；基于起点重复触发使用 `everyPeriod`。服务器校时需要接入项目自己的时间源，后台错过的周期在恢复前台时按接口规则处理。

完整参数、生命周期和调用示例见 [API 使用指南](docs/api-guide.md)，也可在 VS Code 悬停查看源码中文注释。

## 工作台与日常维护

| 页面       | 用途                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| 创建内容   | 模块、资源包、界面、Part、普通预制体、Component、Service 和 XLSX；预览文件与命名冲突 |
| 自动绑定   | 扫描节点、生成 Binding、写入引用，也可接入已有预制体                                 |
| 配置表     | 选择导出目标、校验数据、预览、重算公式和导出                                         |
| 项目设置   | 分包配置、应用标识、音频、日历及框架运行参数                                         |
| 删除与恢复 | 检查引用、备份并删除模块或资源，处理恢复与冲突                                       |

资源和 XLSX 变化后会自动校验并更新生成文件，也可以在工作台手动触发生成和检查。删除模块、资源包或界面时使用工作台的引用检查与备份流程。

场景、预制体和资源移动通过 Creator 完成。保留 `.meta`、`project-settings/generated` 和框架生成文件，并随源码提交，保证资源引用、逻辑身份和生成记录一致。

## 常用命令

首次运行检查前，先用 Creator 打开项目并等待导入完成，以生成引擎类型声明。

| 命令                                      | 用途                                                   |
| ----------------------------------------- | ------------------------------------------------------ |
| `npm ci`                                  | 按锁文件安装开发依赖                                   |
| `npm run verify`                          | 完整检查：代码、格式、类型、框架规则、生成一致性及测试 |
| `npm run lint` / `npm run lint:fix`       | ESLint 检查 / 自动修复                                 |
| `npm run format` / `npm run format:check` | 格式化 / 格式检查                                      |
| `npm run typecheck`                       | TypeScript 类型检查                                    |
| `npm run check`                           | 框架规则和生成产物一致性检查                           |
| `npm run generate`                        | 生成资源清单、配置和 TypeScript 文件                   |
| `npm test`                                | 运行自动化测试                                         |

脚本使用 **4 个空格**缩进，JSON 和 Markdown 使用 **2 个空格**。VS Code 保存时执行格式化与 ESLint 修复；**Ctrl+Shift+B** 运行完整检查，**F5** 连接 Creator 浏览器预览进行调试。

构建时选择 `Bootstrap.scene` 作为启动场景，并配置对应平台参数。框架在构建前检查源码和生成文件，在构建后输出资源包与体积审计报告至 `.yzforge/build-reports`。
